# Video playback foundation

This PR adds a reusable browser player; it does not unblock the TeraBox integration. Real TeraBox API/CDN playback, signed URL behavior, credentials and browser compatibility remain unverified. Mock stays default and the official adapter still fails closed. No resolver, media proxy, cookies, private API, advertising, server-side media storage or OAuth flow was added.

## Files and behavior

- `src/components/video-player.tsx`: HTML5 video with native accessible controls for play/pause, volume, seek and fullscreen. No autoplay; inline playback and anonymous cross-origin mode. Loading/buffering status, 30-second stall timeout and fixed public error messages do not echo URLs or error objects. Browser/platform controls can differ (for example fullscreen and volume behavior on mobile).
- `src/lib/media-policy.ts` / `media-origins.ts`: reject malformed, non-HTTPS, credential-bearing, custom-port, fragment-bearing, IP/localhost, unapproved-origin, non-verified, unsupported-format or expired sources. Verification/expiry must be UTC timestamps. A caller's `verified` flag alone does not grant an origin permission. Approval is checked before creating a video element and before HLS requests.
- `src/lib/hls-playback.ts`: lazy-loaded hls.js **1.7.4**, verified against npm's stable metadata (Apache-2.0). Prefer native MP4, then native HLS when `canPlayType` offers it; otherwise use hls.js/MSE. Workers, interstitials and debug logging are disabled. Buffer targets are modest for client devices; these are not a hard browser memory quota.
- Every hls.js playlist/rendition/fragment/key request goes through the reviewed-origin and expiry guard. Fetch uses CORS, omitted credentials, no referrer, no cache and `redirect: error`; only a valid Range header is retained. The source's signed query is preserved for its intended origin but is never serialized into errors/logs. No cookies or Authorization headers are forwarded. FetchLoader's AbortController cancels active requests on stop/destroy.
- On source change/unmount, the player cancels timers and DOM listeners, pauses and clears native media, calls `load()` to cancel/release the old source, unregisters HLS callbacks, stops HLS loading and destroys the instance/MediaSource. Late lazy-import completion is ignored. Expiry is checked on a bounded timer and play/time/visibility events to handle sleeping tabs. Equivalent source objects do not restart playback.
- `src/lib/workspace-playback.ts` and `workspace.tsx`: an additional gate requires official/live metadata, a verified stream, recognized MIME and approved unexpired URL. Mock/unverified sources remain placeholders. The existing `isResolveResult` quarantine still rejects all verified URLs from provider responses. Removing that quarantine or implementing actual TeraBox metadata is outside this PR.

## Production policy and CSP

`REVIEWED_MEDIA_ORIGINS` is deliberately **empty**. Production therefore keeps `media-src 'none'`, `connect-src 'self'`, and now explicitly sets `worker-src 'none'`. No wildcard, arbitrary HTTP host, fixture origin, blob script or worker exception is granted. The player is dormant in the deployed workspace until authorized integration and media policy review happen. `allowImportingTsExtensions` only permits the explicit native-Node config import; TypeScript strict checking stays enabled.

A future review must approve exact HTTPS CDN origins in code, never from an environment variable, URL input or API response. Review ownership/license, API permission, all HLS subresource origins, redirects, cookie-free cross-origin hosting, MIME/codecs, CORS, byte ranges, signed-URL expiry and sensitive-query handling. Only after approval does the shared CSP builder add those exact media/connect origins and `blob:` **for MediaSource only**. A blob URL from caller input is still rejected. The player does not create worker blobs or enable `unsafe-eval` in production.

Native video/HLS requests are browser-managed: JavaScript cannot intercept each segment or force Fetch's redirect mode. Their containment relies on anonymous CORS, the document's no-referrer header, strict browser CSP for every destination and the reviewed CDN contract. Do not enable an unreviewed native source or relax CSP to work around CORS. hls.js has a per-request guard in addition to CSP. Client checks are not server-side authorization and do not replace official API permissions or SSRF controls.

## Authorized fixtures and reproducible browser checks

See [the synthetic fixture contract](../tests/fixtures/README.md). Generated test-pattern content is project-owned and dedicated under CC0-1.0; it has no third-party footage, sound, TeraBox share, account or CDN dependency. No video file is committed or served by the application. FFmpeg writes temporary generated bytes for the test runner, and cleanup removes them.

Requirements: Node 24, FFmpeg with libx264 and a Playwright-compatible Chromium. The browser runner uses a separate Vite harness, substitutes only the media-origin module for `https://media.terastream.test`, and fulfills that isolated test origin through Playwright with explicit CORS, MIME and range responses. Unrelated outbound requests fail the test. This does not change the application allowlist or introduce a deployment test endpoint.

```sh
npm ci
npm run check
# Install Playwright's Chromium, or use an existing compatible executable:
npx playwright install chromium
npm run test:video-browser
# Existing system Chromium:
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:video-browser
```

Restricted containers may additionally require `PLAYWRIGHT_DISABLE_SANDBOX=1` **for this isolated test only**. Normal local/CI execution should keep Chromium's sandbox enabled. The production application and container security settings do not use this flag. The runner, FFmpeg and browser packages do not run in the final standalone image. Existing GitHub CI runs unit/component tests and the app build; the optional FFmpeg/browser check is separate and not silently represented as a CI pass.

## Validation and limits

Local checks on 2026-10-29, Node 24.19.0:

- Clean `npm ci`, `npm run check`: lint, strict typecheck, **130 tests across eight suites**, production standalone build passed. Tests exercise MP4/native-HLS/hls.js selection, loading/stalls, unsupported browsers/formats, invalid/expired sources, expiry during playback, native/HLS errors, source replacement, deferred initialization/unmount, timer/event/HLS cleanup, workspace gating, request/credential/redirect policy and unchanged production CSP.
- The isolated real Chromium run decoded the generated H.264 frames through **native MP4, native HLS and forced hls.js/MSE**. Play/pause, volume, seek, fullscreen, manifest/segment requests and no unexpected requests/page errors passed. Native HLS was offered by this Chromium build; the forced fallback case overrides only its HLS capability probe, while decoding still uses actual MediaSource.
- `docker compose config --quiet` passed. Provider modes, Dockerfile, Coolify port binding, health route, memory/process limits, SSRF code and MIT license remain unchanged. The added dependencies are pinned and existing versions retained.
- The unchanged Dockerfile built successfully (the managed proxy CA was supplied via its existing temporary BuildKit secret, with TLS verification enabled). The standalone image reached healthy using a temporary loopback mapping and all production Compose hardening. HTTP checks verified health, default mock API, no active video/source, `media-src 'none'`, `connect-src 'self'` and `worker-src 'none'`. Runtime remained UID 1000 and contained no fixture, Vite or Playwright installation. Test container/network were removed afterward; no target VM deployment was attempted.
- `npm audit --omit=dev --audit-level=high` reported zero production dependency vulnerabilities at the time of checking; this is not a security guarantee.

The browser harness verifies controlled synthetic responses, not a real Internet CDN or live authorization. Safari/iOS, Firefox, mobile native-control details, captions/audio tracks, encrypted/DRM streams, live/LL-HLS, long-duration/high-bitrate load and cross-browser signed-URL expiry behavior are not verified. There is no automatic token refresh or download change. Before enabling a real source, add authorized CDN/API integration tests and review the production approval list/CSP separately. **No TeraBox video playback claim is made.**
